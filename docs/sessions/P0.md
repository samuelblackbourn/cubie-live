## 2. What P0 is

One session. The Pi becomes the clean host for cubie.live, with a chosen model, a
measured tick budget, and a proven backup. **No sim code is written in P0.** Output
is three numbers, one decision and a working backup.

## 3. Hard constraints

- **Separate project.** This repo only. Nothing from the `cubie` robot repo, the
  Virtual Office or office-server's services is copied, called or depended on. No
  companion token, no office URL, no gateway.
- **Subscription only, no API tokens.** Ollama is the brain. No Anthropic key, no
  cloud model, no PixelLab yet (that is P3).
- **LAN-only, low trust.** Nothing new listens on the internet. `cloudflared` keeps
  only the existing `ssh.zyla.studio` hostname; the `cubie.live` hostname is P4.
- **Secrets in files, never in shell words or the repo.** `/etc/cubie/*.env`, 0600.
- **Working pattern.** Step-by-step with confirmation at each numbered step below;
  decisions and measurements logged back to the vault (§7); feature branch + draft
  PR for anything that lands in the repo.
- **Never reflash without §4 step 1 done.**

## 4. Steps

1. **Inventory and preserve.** SSH to the Pi (`ssh.zyla.studio` or LAN). Record:
   model, RAM, storage (is there an NVMe HAT and drive? boot device?), OS, kernel,
   what is still running (`systemctl list-units --state=running`), disk usage.
   **Back up `/etc/cloudflared/` and the tunnel credentials to the Mac** and verify
   the copy opens. Back up anything else present that is not reproducible (old
   vault remnants, keys). Confirm with the creator before anything is removed.
   *Stop here if no NVMe: the creator decides whether to order one now and continue
   P0 on SD, or wait. P0 is valid on SD; P1 should start on NVMe.*
2. **Fresh OS.** Raspberry Pi OS Lite 64-bit (Trixie) unless the creator prefers
   Ubuntu Server; hostname `cubie`; user `sam`; SSH keys only; `avahi-daemon` so
   `cubie.local` resolves; unattended-upgrades on; timezone `Europe/London` (the
   island's clock is its own, but logs should be readable). If NVMe: boot from it
   (`rpi-eeprom-config` boot order, image the NVMe, verify boot without the SD).
3. **Restore `cloudflared`** with the saved credentials; confirm `ssh.zyla.studio`
   works again from outside the LAN before continuing.
4. **Baseline services.** `ollama` (official arm64 install, as a systemd service,
   `OLLAMA_KEEP_ALIVE=-1`, bound to `127.0.0.1`), Python 3.12+ and `uv`, Node LTS
   (for P2's build tools only), `git`, `restic`. A `cubie` system user owning
   `/var/lib/cubie/` (the future vault) and `/etc/cubie/`.
5. **Models.** Pull `llama3.2:3b`, `qwen2.5:3b`, `gemma3:4b` (and `qwen2.5:7b` only
   to prove it is too slow). Note on-disk and resident sizes.
6. **Benchmark** — `tools/bench.py` (in this repo), run per model, results to
   `docs/p0-benchmark.md`:
   - a. **Generation**: tokens/s on a 60-token reply.
   - b. **Prompt evaluation**: time to first token on a ~900-token prompt.
   - c. **Prefix cache**: the same 700-token *stable* prefix followed by a
     200-token *variable* suffix, three calls with different suffixes — does call
     2 and 3's time-to-first-token drop? This decides the prompt layout for P1.
   - d. **Structured pick**: Ollama `format` with a JSON schema for `{action,
     target, thought}` where `action` is an enum of 6 options given in the prompt
     (a stand-in for the filtered menu). 20 runs: valid-JSON rate, in-menu rate,
     median latency.
   - e. **Resident RAM and CPU temperature** during d; whether the throttle flag
     trips (`vcgencmd get_throttled`).
7. **The gate.** A model passes if: d ≥ 95 % valid and in-menu, d median ≤ 5 s with
   the cached prefix, b ≤ 10 s cold, no throttling. Rank the passers by d quality
   (the creator reads 20 `thought`s per model and picks — the point is which one
   writes like Cubie). Record: **model, tick length (45 s unless d says
   otherwise), prompt budget (stable/variable token split that keeps d under 5 s).**
8. **Backups.** `restic` repo on office-server over SSH (as a *host* — a file
   target, not an office feature) or Backblaze B2 (the creator's choice; B2 if the
   MacBook ever sleeps). Nightly timer backing up `/var/lib/cubie/` and `/etc/cubie/`
   (encrypted; password in `/etc/cubie/restic.env`). Put a test file in the vault
   dir, back up, **delete it, restore it**, show the restore. Add a monthly
   restore-check timer that restores to `/tmp` and diffs.
9. **Repo.** Fill in `deploy/` (the systemd units and `install.sh` written so a
   fresh Pi can be rebuilt from the repo + the secrets dir; the `cubie-deploy.timer`
   + `pull.sh` skeleton from the master plan §5), `docs/p0-benchmark.md`, and copy
   design notes 02–04 into `docs/design/` from the vault. Draft PR.
10. **Log and stop.** Write the P0 result to the vault (§7). Do not start P1.

## 5. Acceptance

- `ssh.zyla.studio` works; `cubie.local` resolves on the LAN; the Pi boots clean
  with only cloudflared, ollama, sshd and the backup timer running.
- `docs/p0-benchmark.md` has a, b, c, d, e for every model and a named winner.
- A backup exists off the Pi and a restore has been demonstrated.
- Nothing from the office or the robot is on the Pi.
